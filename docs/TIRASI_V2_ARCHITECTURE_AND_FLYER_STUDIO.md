## 0. 設計の原則

1. 「既存イベントHP」と「チラシスタジオ」は別の責務。共通のイベント内容を参照するが、公開サイト表示・編集中下書き・書き出しを混同しない。
2. デザイン変更はデータ破壊を起こさず、イベント本文・出演者・日時・会場・SNSを保持する。
3. 単なる色替えを「新テンプレート」と数えない。レイアウト、文字の階層、装飾、背景表現まで実質的に違うテンプレートを用意する。
4. プレビュー・PNG・印刷/PDFは、原則同一レイアウト定義を使う。書き出し専用の位置補正を積み増さない。
5. すべての書き出しには再現可能な設定と検証方法を持たせる。ブラウザ・フォント・画像処理の限界は利用者に正しく伝える。
6. 画像・フォント・レイアウト処理が失敗した場合は、既存チラシ編集とデータ保存を利用可能な状態で維持する。
7. MVPはブラウザローカルで完結。認証・DB・課金・外部生成AI API・自動デプロイは依頼なしに追加しない。
8. PRを微小分割しない。「安定化」と「スタジオ拡張」の原則2本で実装。途中は同一ブランチへの作業コミットと進捗文書で継続する。
9. mainへの自動マージ・公開デプロイは禁止（明示承認がある場合のみ）。本設計文書を先にmainへ追加することは許可済み。
10. 変更を始める直前にmain SHA・open PR・既存データを再照会。基準SHAと異なる場合は差分を確認して設計を調整し、破壊的に上書きしない。

### 1.2 確認済みコード上の不整合

R01 / **掲載情報の不一致（確定）**  
src/components/Home/HomePage.tsx の説明に「春のイベント」「11:00より営業」が直書きされる。src/components/Home/VisitorInfo.tsx には「15:30開始」が固定記述され、defaultEventの14:30と整合しない。index.html、OGP画像も前回vol.5の情報。対応: 表示・SEOデータの出典を統一し、固定イベント文言を入力データ化または不要項目として抑制。

R02 / **出演者紹介トグルがA4に効かない（確定）**  
FlyerOptionsEditorが flyerOptions.showPerformerProfiles を編集するが、現行 /flyer は OnePageFlyer を直接使用。FlyerPerformerProfilesは存在しても現行表示経路で利用されない。対応: 共通のレイアウト・条件付きパーツへ接続し、0名、1名、5名以上をテスト。

R03 / **公開表示と下書きデータの混線（設計上の問題）**  
useEventData は初回にブラウザlocalStorageを採用し、そのeventDataを / と /flyer にそのまま表示。公開defaultEvent更新後にも同じブラウザの旧localStorageが勝つ。編集者自身には「未公開編集が公開HPへ反映された」ように見えるが他端末とは一致しない。対応: publishedEvent と workspace draft を分離し、閲覧者の / と /flyer は公開ソースを表示。編集画面では「編集中」と「公開済み」を明示。明示的な下書きプレビューは別導線。

R04 / **インポート時の構造検証不足（確定）**  
EditorPageのisEventDataは一部フィールドと配列有無のみチェック。safeParseEventData / safeParseEventLibrary / normalizeEventData も一部だけを検証する。例えば venue は真偽値判定のみで venue.url が文字列である保証がない。読み込み後の .replace や .map が失敗する可能性。対応: バージョン付きスキーマ検証、欠損補完、サイズ制限、エラー詳細、無効ファイルを無変更で拒否、後方互換テスト。

R05 / **URLの未検証（確定）**  
HomePage / FlyerView / PerformerProfiles に編集値からのhref、img srcを直接設定する箇所あり。URLはhttp/httpsのみを許容し、表示文字列を別に扱う。PR #21の方向性を再評価する。注意: これはクライアントのデータ入力リスクであり、サーバーへの第三者による改ざんを示すものではない。

R06 / **クライアントパスコードは認証ではない（確定）**  
EditorGate.tsxの固定値はビルド配布されるコードに含まれる。実際の公開データを変更できる権限認証ではなく、ローカル編集画面を隠すだけ。対応: 誤解のない表現とUI。秘密値と見なさない。真の共通管理認証が必要になれば別途サーバー認証を設計する。環境変数の名称だけ変えて「安全化完了」としない。

R07 / **書き出しレイアウトの単発補正（確定）**  
one-page-flyer.cssの export-image-copy 固有セレクタにmm単位のtranslate等が多い。プレビューとPNGの不一致や、文章の長さによる欠けが起きやすい。one-page-sheetは297mm固定、overflow:hidden。対応: 書き出し専用の位置違いを排除し、同じ描画面からexport。溢れ判定→修正案提示またはページ分割。黙って文字を切らない。

R08 / **PNG共有の非決定性（高い再現リスク）**  
PNG生成がawait後となり、モバイルSafari等ではユーザーアクティベーションを失ってWeb Shareや新タブがブロックされ得る。canvas.toBlobコールバックも外側のtry/catchとは別の非同期境界。二重実行制御なし。対応: 生成後に「保存」「共有」ボタンを有効化し、共有ボタンのユーザー操作でAPIを呼ぶ。タイムアウト、失敗メッセージ、Blob URL解放、連打制御をテスト。

R09 / **ブラウザ保存の失敗耐性不足（コード上の懸念）**  
localStorage読込・書込の一部がtry/catchなし。ストレージ制限・無効化・容量超過時の例外が画面に伝わらない。データをメモリ内に保持し、保存失敗時は未保存状態を明示してJSONバックアップ導線を出す。複数タブ競合も警告する。

R10 / **日付・曜日の二重入力と古い案内**  
日付と曜日は別の自由入力。矛盾に気づけない。READMEとEventManagerの説明にはvol.5基準の文言が残る。対応: 正規化された日付・タイムゾーン（Asia/Tokyo想定）から曜日を算出し、表示形式だけ自由に変更可能にする。互換読込にはパーサと警告が必要。

R11 / **バックアップ・データ復元の長期保守性**  
イベント単体JSON、一覧JSON、公開用JSONにバージョン番号なし。ID重複や異常データ、将来のスタイル拡張の移行方法が定義されない。対応: スキーマversionとmigration、検証、バックアップ互換、インポート前プレビュー。

R12 / **テスト欠如、再現性の不足**  
package-lock.json未追跡、CIはnpm installとbuildのみ。単体テスト/E2E/Visual Regression/PNG実測/アクセシビリティテストがない。対応: lockfile + npm ci、Vitest、Playwright（必要ブラウザはCI環境を考慮）、決定的なfixtures、最小基準画像。

## 2. 目標アーキテクチャ

### 2.1 データと公開面を分離

- PublishedEvent: リポジトリにコミットされた公開用ソース（静的JSON/TS）。/ と通常の /flyer はこれのみ読む。
- EventWorkspace: 編集者端末のイベント一覧（draft、activeDraftId、更新時刻、schemaVersion）。
- PreviewMode: 編集画面から明示的に開くローカル下書きプレビュー。公開済み画面との差異を見分けられる。公開用 /flyer には遷移させず、draft専用のプレビューを用意する（DA-03）。
- CreativeDocument: event-flyer / free-flyer / image-treatment の判別可能な制作物。イベントに紐づかない自由制作と既存画像加工も扱える（DA-01）。
- FlyerDesign: 制作物に紐づく表現設定（templateId、paletteId、sizeId、typographyId、decorations、画像アセット参照、セクション表示設定）。
- AssetStore: 大きな画像はIndexedDBに格納、一覧メタデータと参照IDだけをworkspaceに持つ。localStorageにbase64画像を詰めない。
- PublicationExport: 「公開用データを書き出す」はあくまでGitHub反映のためのファイル生成。公開完了と誤表示しない。サーバー自動更新なし。

### 2.2 推奨型（概念）

- EventContent: id, title, subtitle, edition, dateISO, timezone, startTime, description, venue, admission, organizer, schedule[], performers[], openMic, socials[]。
- EventDraft: schemaVersion=2, id, name, content, design, updatedAt, publishedSourceRevision?。Eventの事実と個々の制作物のデザインを分離する移行用の概念型。
- CreativeDocument: schemaVersion, id, kind(event-flyer/free-flyer/image-treatment), name, contentBlocks, eventBinding?, design, assetRefs, updatedAt。イベントのOpen Micやscheduleを自由制作に強制しない。
- FlyerDesign: templateId, paletteId, canvasSizeId, fontSetId, visibility, textOverrides?, background, illustrationAssets?, printOptions?。
- TemplateDefinition: id, displayName, family, preview, supportedSizes, layoutKey, sectionCapabilities, minFontSize, safeArea, decorationKind, defaultPalette, defaultFonts。
- AssetMetadata: id, name, mime, width, height, bytes, updatedAt, alt?。

型定義とバリデーションは一つのモジュールに集約。レガシーEventDataの内容をlosslessに移すため、当初は旧フィールドも読み込めるadapterを置く。既存のactive event、プロフィール、URL、showPerformerProfilesを失わない。初期データ移行は冪等、成功を検証してから旧保存データを退避・整理する。新旧形式が混在しても、旧形式を不用意に上書きしない。

### 2.3 レンダリング境界

1. EventContent → 正規化済み view model（日時・URL・行数・ラベル・非表示セクション）。
2. FlyerDesign + canvasSize → TemplateDefinitionを選択。
3. TemplateRenderer: 共通のデータ入力に対し、実際に異なるレイアウトレシピを描画する。
4. FlyerCanvas: CSSで固定の物理/ピクセル寸法を管理。画面プレビューは外側コンテナを縮小表示するのみ。内部の紙面寸法をviewportに応じて変更しない。
5. ExportRenderer: 画面/PNG/印刷で同一のレイアウト**仕様**とデータを共有する。ブラウザやhtml2canvasのCSS非対応を考慮し、DOM/SVG/Canvas 2D/印刷CSSの別adapterを許容する。機能別capabilityMatrixを持ち、フォント/画像を準備してから描画する（DA-06）。
6. OverflowDiagnostics: 実DOM境界・行幅・安全領域・描画完了後のサイズを計測。エラーを可視化。必要時は紙面複数ページ/密度プリセット/セクション短縮を提案。
7. 共通印刷パスは最初にA4で確立し、その後別サイズへ展開。テーマ切替時に旧A4互換を検証。

### 2.4 UIの基本フロー

ホーム: 公開中イベントを表示。  
編集: 「イベントチラシを作る / 自由制作チラシを作る / 既存画像を加工する」を選ぶ → 必要な本文・画像入力 → デザイン選択 → 調整 → **下書き専用**プレビュー → 書き出し。  
デザイン: 「時代/雰囲気」「レイアウト」「配色」「文字」「装飾」「サイズ」を独立選択できる。選択直後にプレビュー反映。  
書き出し: 「PNG生成」→完了後「保存」「共有」、「PDF/印刷」。失敗時は原因と代替操作を示す。  
公開: 公開データ出力 → 手動でGitHub反映 → CI/プレビューで検証 → 必要時に手動デプロイ。公開をクリックだけで完了したように見せない。

## 3. Flyer Studio：大幅なテンプレート拡張

### 3.1 テンプレートをテーマ（色）から独立させる

現行 themeId だけでは4種類の配色差に留まる。新たに「構図」「時代感」「印刷表現」「強調する情報」を独立させ、templateId + paletteId + fontSetId + decorationsを組み合わせる。個々のレシピは名前を変えただけの同じDOMにしない。全テンプレートで共通の型と書き出しAPIを利用する。

### 3.2 最終必須テンプレート一覧：20種、8ファミリー

### 3.3 カラーパレット、フォント、仕上げ

- 12以上の配色セットを用意。春/夏/秋/夜の既存パレットを引き継ぐ。配色はレイアウトから独立。
- 日本語で読みやすい複数のフォント組（見出し/本文/数字）。外部フォント取得不能時もレイアウトが致命的に崩れないフォールバックを定義。
- 装飾スイッチ: 粒子、網点、軽い版ズレ、手描き枠、斜め帯、紙テクスチャ、スポットライト、幾何学模様、写真フレーム、余白バランス。
- 「80年代風」の場合、全プリセットを単に褐色に古びさせない。1985当時に新品だった印刷物と、現代に残る経年劣化版を分ける。紙の傷・褪色・日付スタンプは明示的に選択する。
- ジェネリックなデザイン名・説明を使用し、第三者の商標や既存広告を無断で模倣しない。

### 3.4 入力できるアセット

- ローカル画像アップロードで背景写真、主役イラスト、ロゴを配置（初期対応: PNG/JPEG/WebP）。
- ファイル形式・最大サイズ・最大画素数を検査、壊れた画像は拒否、スマホ画像の回転を考慮。
- 画像はcrop、contain、位置X/Y、拡大率、透明度を調整。文字と画像が干渉するときは安全領域とコントラスト警告。
- データ本体とバイナリアセットを別管理（IndexedDB）。URL.createObjectURLは解放。
- バックアップは「JSONのみ」と「アセット同梱パッケージ（マニフェスト+画像）」を区別。画像なしJSONを全体バックアップだと誤認させない。
- SVGアップロードは初期対象外（安全なサニタイズ基盤なしにユーザーHTML/SVGを注入しない）。
- 写真・イラストが無い場合も、CSS/SVG等の内蔵グラフィックだけで完成見栄えを作る。
- GitHubにはユーザーの未承認画像を勝手に追加しない。会話で示された参考画像も自動的にリポジトリアセットと扱わない。

### 3.4a 既存画像・完成チラシを80年代風に加工するモード

ユーザーは「イベント情報から新規にデザインする」と「手元のポスター/写真/チラシを取り込み、元の内容を維持してレトロ調に仕上げる」を選べる。後者は新規レイアウト20種とは**別のワークフロー**であり、テンプレート数へカウントしない。

- 取り込んだ元画像を保持したまま、加工パラメータ（filterPresetId, grain, halftone, fade, warmth, colorShift, registrationOffset, paperOverlay, vignette, scratches, dateStamp, crop）を非破壊で記録。いつでも初期状態へ戻せる。
- ローカル画像向けプリセット例: **1985 新品印刷**, **1985 経年ポスター**, **昭和コピー機**, **リソグラフ2色刷り**, **ネオンライブチラシ**, **古いフィルム写真**。単一のセピア化を「80年代風」と呼ばない。背景・文字をむやみに変形させない。
- 元画像の構図と文字の保持を優先し、色・印刷質感・写真風の光・紙の傷を編集する。透視補正、消しゴム、人物や描画物の内容変更は初期必須に含めない。
- 画像を画面中央に表示し、左右比較/スライダー等のBefore/After比較を提供。変化をプレビューで確認してからPNGへ書き出せる。
- 加工効果はCanvas 2Dまたは書き出し互換の描画手段で**画面プレビューと保存結果を一致**させる。CSSフィルタのみでプレビューし、PNGでは消える構成を採用しない。
- フィルムの日付スタンプ、色の版ズレ、粒子、擦れはON/OFF・強度調整が可能。日付は実際の撮影日を装って固定入力しない。日付スタンプを入れる場合はユーザーが選ぶ。
- 高解像度画像をスマホに一度に複数展開しない。ピクセル上限、段階的プレビュー解像度、キャンセル、メモリ不足の説明と安全な書き出しサイズを用意。
- 画像ファイルはIndexedDB等へローカル保存。リモートAPIに勝手に送信しない。データ持出しには明確なユーザー操作が必要。
- この機能は「フィルター/画像処理」であり、画像内容を理解してAIが再描画する image-to-image 生成とは異なる。生成AI機能の追加は別途選択・プライバシー/料金/権利確認を経て設計する。
- 参考写真がチャット上にあるだけではアプリの素材に自動追加しない。アプリ内アップロードを使う。

完成判定: 元の文字・配置が保持された既存チラシ画像を取り込み、最低6加工プリセットを切替でき、強度調整とBefore/After、PNG書き出し、再編集用保存が成功する。色調だけでなく網点・版ズレ・擦れ・フィルム感の表現差が確認できる。

### 3.5 用紙・画面サイズ

- 必須4出力: A4縦（210×297mm; PNG 300dpiは2480×3508pxを基準）、SNS縦（1080×1350px）、SNS正方形（1080×1080px）、ストーリー（1080×1920px）。SNSはPNG、A4はPNGとブラウザ印刷/PDF保存の導線を保証。
- A5とA4横は拡張目標。サイズが変わる場合は単なるscaleではなくセクション再配置ルールを指定する。
- PNGは意図したpx寸法を明記し、PDF/印刷は実寸・余白・背景色・裁ち落としの扱いを明示。
- 文字の可読最小サイズとセーフエリアをレシピごとに定義。情報が多い場合、見えないまま切り捨てない。
- イベント詳細を印刷したい用途と、SNS告知用に内容を絞る用途を分ける。文言の省略はユーザーが確認できる可視の設定とする。

## 4. 安定化の実装要件

### 4.1 保存と復元

- schemaVersion=2を導入し、v1の単体イベント・一覧・activeIdを読み込める migration を用意。
- schema検証はunknown入力→検証→正常な型付け→表示という順序に統一。null・配列・入れ子型・項目数・文字列長・URL・ID重複を検査。
- Importは一旦「置き換えプレビュー/件数確認」を表示してから確定し、拒否時は現在のデータを無変更。
- JSONのエクスポートとインポートの往復で内容を失わない（round trip tests）。
- Storageエラーを握り潰さず、未保存バナーと即時バックアップ導線を提供。
- 大容量画像のIndexedDB破損・取得失敗ではプレースホルダーとエラーを示し、イベント本文を守る。
- 複数タブ同時編集は最低限、保存世代番号/updatedAt比較で競合警告。自動で黙って上書きしない。
- 状態更新で現在activeIdを誤って参照しないよう、イベント切替や複製と連続入力のraceをテスト。

### 4.2 公開と下書き

- 公開閲覧者に他人のローカル下書きが混ざらない（公開値はrepoのpublished source）。
- /editorはローカル編集ワークスペース。ゲートを残すなら「合言葉は秘匿認証ではない」文言を明記。
- 「保存」「下書きプレビュー」「公開用データ書き出し」「実際の公開」を別々のステータスにする。
- 公開用のファイルを生成できてもサーバー上の更新ではないと明記。
- データ差分（タイトル、日時、演者、場所）が公開値と異なる時は視認可能な区別を付ける。
- 外部リンクはhttp/httpsのみ許容。非URLや無効値は安全なテキストとして表示。
- 開発者が認証・DBの追加を自己判断で行わない。

### 4.3 画像・印刷

- png exportステータス: idle → preparing → ready → sharing/downloading → success/error。
- ユーザー操作で「PNGを生成」、完了後の別のユーザー操作で「保存」「共有」。
- Web Share不可の場合はダウンロードへフォールバック。ポップアップ依存を唯一の保存手段にしない。
- 生成中の連打ブロック、canvas.toBlob null、CORS画像不読み込み、フォント待ち失敗、timeout、低メモリ端末を考慮。
- 背景の透過、背景色、フォント描画、テーマ、長い文字列、余白、紙面外overflowをテスト。
- 対応外の装飾をPNGだけ異なる形で描画してはいけない。出力可否をレシピのcapabilityとして定義。
- PDFの独立生成ライブラリは必須ではない。まずwindow.printで実寸に対処する。
- テキストが収まらない時に全紙面を0.6倍に縮めるような不可読解決は禁止。

### 4.4 公開メタデータ

- index.html内のタイトル・description・OGP・JSON-LD、og-image.svgの値を、実際の公開イベントに合わせる仕組みを実装する。
- 静的ホスティングでのビルド時生成（publishedEventを入力とするスクリプト）を第一候補にする。必要ないのにSSRを追加しない。
- startDate、timezone、venue、出演情報が構造化データと合っていることをテスト。
- 新イベントへの切替時に前回のvol.5が残っていないか検査。
- SEO/OGP画像はWeb公開面の情報。下書き変更だけでは勝手に更新されない。

### 4.5 旧コード・見た目の整理

- 現行A4と新テンプレートのデザイン互換用にlegacy templateを残す。
- FlyerViewとOnePageFlyerの役割を特定し、不要な重複はテスト後に廃止する（消した結果、editor preview/旧表示を失わない）。
- CSSのグローバル上書きの衝突を整理。テンプレート固有スタイルを名前空間化して他テンプレートに漏らさない。
- 表示時のA4 fit警告を実際の測定へ段階的に切り替える。
- 旧色テーマ4種を残し、新しいテンプレートへ安全に移行できるようマッピングを定義。
